# 相关工作与结论边界

## 已有工作与本项目范围

| 工作 | 原文中的范围 | 与当前 AutoHLS 的关系 |
| --- | --- | --- |
| [HLSPilot，2024，v1](https://arxiv.org/html/2408.06810v1) | 分析程序并生成/优化 HLS 代码，检索厂商优化文档；实验使用 GPT-4、Alveo U280 和 GenHLSOptimizer 参数搜索（III、IV-A 节）。 | 已覆盖模型辅助 HLS 和软硬件加速流程。当前项目不是这类流程的首创，也未复现其整套代码变换与部署。 |

| 当前 AutoHLS | 三个固定尺寸整数内核；模型只能从尚未评估、协议允许的 pragma 配置中选取 ID；原生、C 仿真、HLS、入选方案 RTL 分层验证；原始请求/报告可重算。 | 可演示低成本工具链、约束候选协议和证据审计。是否提高搜索效率，需要同预算随机及无反馈对照；功能测试并非全输入域形式化证明。 |

以上是按各文原文范围做出的定位判断，不意味着对其完整实现的独立验证。论文中“首次”等作者自述不在本项目沿用。

## 当前可以与不可以声称的内容

- 可以：合法候选 Schema 修复了已观察到的重复 ID 问题；固定预算对照保留所有失败、原始模型响应和综合报告，支持逐项核验。
- 可以：在指定 PYNQ-Z2、矩阵乘批量和驱动条件下报告已有板级成绩，并链接[独立板级报告](HARDWARE_BATCH_BOARD_20260926.md)。不得把这些成绩归因于本轮尚未上板的模型胜出方案。
- 尚不能：有反馈必然优于无反馈/随机；适用于任意 C/C++ 或任意 FPGA；胜过 HLSPilot/LLM-DSE；实现了模型驱动功耗优化。
- 不可混用：HLS 估计周期、RTL 协同仿真通过、布线后时序和板上端到端计时，是不同证据层。HLS 最快配置若 RTL 失败，必须拒绝并记录后备，不能重写原始 HLS 搜索成绩。
- 候选 ID 在 Schema 内，只表示满足选择协议，不表示一定能综合或满足时序。例如本轮卷积的部分数组分区因子被工具拒绝；这些真实失败也计入预算。

## 对完整对照的解释规则

原[预算8固定27组方案](MODEL_SUITE_20260927.md)与[预算16方案](MODEL_BUDGET16_20260927.md)均已完成独立审计及RTL验收，两批启动后均未因中途成绩调整模型、提示或预算。模型两次固定参数重复只检验稳定性，不当作独立随机样本；随机五种子保留中位数和最差值。费用/时间讨论同时给出模型调用和综合成本；加载、缓存与系统负载可能影响墙钟，未经隔离实验不把耗时差异单独归因于某一因素。

若最终有反馈组没有优势，应如实作为负面结果。之后如调整反馈或探索策略，需新建版本、重新固定对照计划，并将现有三个内核标为已用于开发的内核；不能把针对这些结果调出的策略再称作未见任务泛化验证。

预算16实际结果：反馈在卷积上优于无反馈，但RTL筛选后与随机同为25.49μs中位数，且搜索耗时更高；矩阵乘与FIR也未显示反馈优于随机。结论限于当前模型、提示、空间、约束和内核，不能推广为所有模型无效。原HLS卷积参考21.57μs再次被RTL拒绝，应展示原始排名与后备，而不是删除该负面结果。

预算8与预算16之间增加了失败诊断传递，因此两批不是仅预算不同的单因素对照。每批内部的随机/无反馈/有反馈才使用相同版本直接比较。还需区分工具失败与约束不可行：例如预算16前两组FIR共32次HLS综合成功，但分别只有2/16、1/16满足10 ns约束；低估计时延不能覆盖时钟不达标。阶段数据来自 `snapshot-05-audit.json`，不是全批或板级结论。
