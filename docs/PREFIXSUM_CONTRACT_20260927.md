# 前瞻迁移内核：256点整数前缀和契约

2026-09-27，在预算8/16、39组排列、42组覆盖结果完成后选择本内核。选择依据是跨迭代累加依赖与现有乘加内核不同，不依据本内核的模型选择或HLS性能；建档时没有这些测量。它只是在本项目策略开发过程中未使用的任务，不保证预训练模型未见，也不能由一个内核推断广泛泛化。

## 固定语义与范围

- 函数：`void prefixsum(const int16_t input[256], int32_t output[256])`。
- 包含当前位置的前缀和：`output[i] = sum(input[0..i])`，0 ≤ i < 256。
- 输入元素为整数[-1000,1000]，输入与输出是独立、不重叠且长度足够的缓冲区；不支持原地调用或动态长度。
- 每次调用重新从0累加，无跨调用状态；输入保持不变，输出256项全部写入，不访问缓冲区外元素。
- 任意前缀绝对值 ≤ 256000，int32累加不溢出。参考算法采用int64对每个前缀重新求和，不复用待测实现的一次扫描递推。
- 顶层源码不预设流水、展开或分区；目标循环标签`SCAN`，数组分区只作用于`input`的第1维。

## 候选与测试（看性能结果前固定）

沿用现有生成器的30个配置：pipeline_ii ∈ {0,1,2}、unroll ∈ {1,2,4,8}、partition ∈ {1,2,4,8}且partition ≤ unroll。0/1/1为无pragma基线。不依据本内核性能删除候选或改覆盖规则；原生C++会忽略pragma，通过不代表HLS/RTL可行。

固定32次连续调用：全0、全+1000、全−1000、交替±1000、首项正脉冲、末项负脉冲、−128至127斜坡、前半+1000后半−1000，以及24个固定LCG序列用例，种子20260927。逐次比较256项输出、256项输入保持和输入/输出各2个前后哨兵，共16512项检查/配置。输出预填域外哨兵，遗漏写入不可伪装通过。连续调用用于拦截跨调用累加状态。

故障注入必须拒绝：exclusive替代inclusive、每步重置累加器、漏末项、int16窄累加器、跨调用静态状态、输入篡改、输出倒序、整段漏写；另外分别在测试台内破坏四个合法哨兵成员，确认边界检查有效。故障样本只用于测试，不能进入性能排名或真实模型请求。

本地准备代码单独持有`Benchmark`对象，不将此内核加入`BENCHMARKS`；因此旧`research all`和已有27/39/42组协议仍只包含原三个内核。现有三内核审计器/报告器不能直接用于新内核，未来先完成独立入口与审计再启动真实实验。

## 未来实测方案边界（未启动）

预期最小方案为单内核14组：无覆盖随机seed0–4、覆盖随机seed0–4、覆盖无反馈/有反馈各2次固定参数重复；每组预算8，总112次候选评估、28次模型提议上限。继续使用原模型、提示、覆盖规则、时钟和资源约束，不同时改合法性过滤或排列。失败占预算、不重试、不因结果追加种子。两个随机策略分别统计，不作逐seed配对。

主比较为同覆盖模型相对覆盖随机，同时保留随机覆盖增量和反馈增量；先报告每组是否完整、可行率、实际HLS时延及成本，最终方案须独立RTL筛选。没有事前30点HLS参考，不为“命中最优”补造标签；不为获取参考而先全枚举本内核性能。本轮不作板级收益声明。
