- 三个 DDR 指针仍为连续 int32 存储，矩阵步长 4096 字节。每个端口最多 64×1024 个 32 位元素，即 256 KiB，三端口最多 768 KiB。
- 新增 uint32 `batch_count`；有效范围 1–64，非法计数直接返回，不进入输入、计算或输出循环。无 auto-restart、并行 DDR 主端口、新外设或外部模块。
- 控制基址要求 `0x43C00000`；构建收集器要求 a/b/c/batch_count 的寄存器偏移为 `0x10/0x18/0x20/0x28`、指针与计数均 32 位，并交叉核对生成头文件与 HWH。实际生成结果通过该检查后才能作为交付包。
- 输入域仍为 [-1000,1000]，内部 int16 乘法、int32 累加；32 项最坏绝对和 32,000,000，不溢出。没有声称任意 int32 输入都适用。

## 测试设计及已得证据

`matmul_batch_axi_tb.cpp` 连续执行计数 `[0,1,2,3,4,16,63,64,1,65,0xffffffff]`，共 11 次调用、154 组有效矩阵。覆盖零矩阵、正负域边界、单位阵及固定种子的随机输入。每次检查整个 65536 元素输出区：共 157,696 项有效结果和 563,200 项未使用区域哨兵比较，总计 720,896 项。参考实现使用 int64，反向遍历乘加，测试种子 20260926。

- 云端原生 C++ 正向程序通过；错误步长、漏算最后一组、错误结果、非法计数被错误夹到 1 的四种故障注入均被拒绝。
- 原生 AddressSanitizer/UndefinedBehaviorSanitizer 构建通过；另以空指针调用三个非法计数，检查其不解引用。该空指针测试不送给 HLS 协同仿真的指针封装器。
- Vivado HLS 2019.1 的 C 仿真和 Verilog 协同仿真通过相同 11 次调用及完整输出检查。协同仿真不是全系统 DDR、PS 或板级复位行为证明；也不是全部输入域的形式化验证。
- 原生范围检测能够捕获数组界限错误；协同仿真检查声明的 65536 元素空间及小批量尾部哨兵，不把它写成完整的外部 AXI 越界监视器。
- 本地回归 61 项：56 通过、5 跳过（3 项 C++ PATH，2 项 Linux 专用）。云端同一冻结源码回归 61 项：53 通过、8 跳过（7 项 NumPy 测试依赖、1 项未上传的历史包证据）。两端相互补齐跳过项，但不把某端的跳过写成通过。

HLS 保留不能展平循环、AXI 仿真深度提醒、工具编译环境提醒和有效时钟预算警告。估计 8.932 ns 大于扣除 uncertainty 后的 8.75 ns 预算；实际是否满足 100 MHz 要以布局布线后报告为准。
